2. Connecting to the robot

2.1 SSH (Linux / macOS / Windows 10+)

ssh spark@10.24.170.0
# password: simple2026

2.2 Windows GUI client - MobaXterm

MobaXterm is Windows-only. Install it from M-Robots 半自动赛资料/Tools/MobaXterm_Installer_v26.6.zip (run the MSI with the DAT file in the same folder). Create a new SSH session:

FieldValue

Port22
Usernamespark

On Ubuntu, use the terminal ssh command or Remmina (SSH/SFTP/VNC).

2.3 If the IP changed

The robot gets its address over DHCP; it can change after a reconnect. On the robot:

hostname -I
ip -br addr show wlo1

Or press the robot's AP/network button once - Spark announces its current IP.

2.4 GUI programs over SSH (RViz, OpenCV windows)

SSH sessions have no display by default. Before launching anything graphical:

export DISPLAY=:0
export XAUTHORITY=$HOME/.Xauthority

Windows then appear on the robot's own screen. For X forwarding from your PC, connect with ssh -X spark@10.24.170.0.

4. Starting the camera and the arm

4.1 Camera + base + lidar

cd ~/spark_noetic
source devel/setup.bash
roslaunch spark_bringup driver_bringup.launch camera_type_tel:=d435 lidar_type_tel:=ydlidar_g6

Verify the stream in another terminal:

rostopic hz /camera/color/image_raw    # expect about 30 Hz

Live view (on the robot screen):

export DISPLAY=:0 XAUTHORITY=$HOME/.Xauthority
rosrun image_view image_view image:=/camera/color/image_raw

4.2 Arm driver (uArm)

cd ~/spark_noetic
source devel/setup.bash
roslaunch swiftpro pro_control_nomoveit.launch

Check that the arm is detected first:

lsusb | grep -E '2341:0042|2e88:4603'
# 2341:0042 = uArm, 2e88:4603 = Sagittarius

Warning: If the arm is not in lsusb, power on the arm and check its USB cable to the expansion dock. Calibration and motion commands do nothing without it.

5. Hand-eye calibration (arm + camera)

5.1 Prerequisites

  • Camera mounted upside-down, looking down.
  • Red calibration block attached directly above the suction-cup mount.
  • Arm powered; e-stop released.
  • Display environment exported (section 2.4).

5.2 Run

export DISPLAY=:0
export XAUTHORITY=$HOME/.Xauthority
cd ~/spark_noetic
./onekey.sh        # 8 (arm-camera calibration) -> 2 (uArm) -> Enter

Two OpenCV windows open (the main one is titled win_draw). Rotate the D435 so the red block lies inside the green rectangle, then press any key in the helper terminal (or publish the start message manually):

rostopic pub /start_topic std_msgs/String "data: 'start'" -1

The arm moves through 20 poses. At 20/20 it writes ~/thefile.txt and prints two regression lines. Press Ctrl+C in the launching terminal to stop.

5.3 Calibration file format

k1 b1 k2 b2
x = k1 * yc + b1
y = k2 * xc + b2

xc, yc = blue/red object centroid in pixels; x, y = arm coordinates in mm.

6. Moving the arm manually

Topic: /position_write_topic, type swiftpro/position (float64 x, y, z).

# hover 20 mm above a point
rostopic pub -1 /position_write_topic swiftpro/position "{x: 198.8, y: 0.6, z: 20.0}"

# lower onto the object (touch / pick height)
rostopic pub -1 /position_write_topic swiftpro/position "{x: 198.8, y: 0.6, z: -50.0}"

# home
rostopic pub -1 /position_write_topic swiftpro/position "{x: 120.0, y: 0.0, z: 35.0}"

Or use the helper script (section 8):

python3 ~/codes/arm_move.py --x 198.8 --y 0.6 --z 20
python3 ~/codes/arm_move.py --home

Note: The arm moves directly to the pose. Keep hands clear. If it stops short, use z = -60; if it presses too hard, use z = -40.

7. Blue-box detection

7.1 HSV thresholds

The grasp demo originally used H 100-130, S >= 90, V >= 80. The light-blue cube in the lab has mean H 86, S 75, V 142, which fragmented under that filter. The detector was patched to:

LowerBlue = np.array([90, 50, 50])
UpperBlue = np.array([135, 255, 255])

Original file backed up as ~/spark_noetic/src/spark_app/spark_carry/nodes/s_carry_object_cv3.py.bak_20261113.

7.2 Stability check patch

The demo required the centroid to move no more than 2 px for 20 consecutive frames, which never happened with the real camera (1-4 px jitter per frame). Patched to:

if found_count >= 10:
if abs(xc - xc_prev) <= 6 and abs(yc - yc_prev) <= 6:

8. Grasp demo (visual pick)

8.1 Start via one-key menu

cd ~/spark_noetic
./onekey.sh        # 9 -> 2 (uArm) -> 1 (fixed position) -> Enter

Put a blue object in front of the robot. The launch opens RViz and a helper terminal. Press any key in the helper to start, which calls:

rosservice call /s_carry_object "type: 1"

8.2 Start directly (survives SSH drops)

cd ~/spark_noetic
source devel/setup.bash
export DISPLAY=:0 XAUTHORITY=$HOME/.Xauthority
setsid nohup roslaunch spark_carry_object spark_carry_object_only_cv3.launch \
  camera_type_tel:=d435 lidar_type_tel:=ydlidar_g6 > ~/grasp.log 2>&1 < /dev/null &

# trigger the grasp
rosservice call /s_carry_object "type: 1"

8.3 Expected state machine

GRASP_OBJECT -> NAV_TO_WAYPOINT -> RELEASE_OBJECT

To stop the demo:

pkill -INT -f "roslaunch spark_carry_object spark_carry_object_only_cv3"

9. HarmonyOS competition / star board (Spark-H)

9.1 Driver commands

source ~/spark_noetic/devel/setup.bash
source ~/UBUNTU20_0/devel/setup.bash
export ROS_PACKAGE_PATH=$HOME/UBUNTU20_0/src:$ROS_PACKAGE_PATH

# manual match:  roslaunch spark_hm_pi_manual hm_spark.launch

For the full task program, roslaunch spark_hm_task_match run.launch already includes hm_spark.launch - do not start it twice. The task starts when hm_task_match_start (String) is published.

9.2 Star board (星火派) connection

  • Serial device: /dev/SPARK-HM-PI (115200 baud); base: /dev/sparkBase.
  • Network config: /home/spark/wifi_info.txt is sent to the board over serial when the driver runs.
  • Current config: SSID OpenHarmony_2, board IP 192.168.124.121, gateway 192.168.124.1.
  • Press Reset on the board after starting the driver. Dot-matrix display: yellow cross = waiting for network, red check = connected.
  • The phone must be on the same network; in the app enter 192.168.124.121 and the app's port.

Note: The HarmonyOS phone app is not included in the documentation pack. The project is a DevEco Studio application (bundle com.example.carcontrol1); ask the organizer for the "鸿蒙比赛APP" project or a signed HAP. The app project contains pages tcpTest, autoPage, index and autoMatch.

13. Safety

  • The arm moves immediately when a pose is published; keep hands, cables and the field clear.
  • Keep the emergency stop within reach; it must be released for the base/arm to move.
  • Charge the robot before long runs; a low battery can shut the NUC down mid-run and drop the SSH session.
  • Do not run two launches that both start the camera or the arm (duplicate drivers cause conflicts).
  • The competition programs must not be modified beyond the allowed software scope; keep the backups above.
