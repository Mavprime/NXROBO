Spark Semi-Auto - Boot & Run

This board is the M-Robots / OpenHarmony Spark. Its ROS Noetic install lives in /data/local/release, and every ROS command goes through the /system/bin/run wrapper, which sets PATH, LD_LIBRARY_PATH, PYTHONPATH and the ROS_* variables. There is no spark_noetic and no source setup.bash on this board - that is the other (Ubuntu) Spark.

Code on the board lives in /data/local/codes/. / is a read-only filesystem, so ~/codes (= /codes) cannot be created. SSH user root, password 123456.

Order of operations

#WhereWhat
1robotPower on, wait for Wi-Fi
2PCFind the board's IP (DHCP - it changes)
3PCUpload semi/ if they changed
4robot, terminal 1Start the server (master + drivers)
5robot, terminal 2Run the Python script
6robotVerify / stop

1. Find the board's IP

On the robot (screen or existing shell):

ifconfig wlan0

Or from your PC with the USB cable connected - no IP needed:

~/bin/hdc shell ifconfig

Read the inet addr on wlan0. The address is DHCP, so re-check after every boot instead of reusing the old one.

2. Upload new scripts (from your PC)

rsync is not installed on the board and ~/codes does not exist, so the usual rsync ... root@ip:~/codes/ fails. Use hdc over USB.

First create the directory on the board - hdc does not create it, and without it every send fails with [Fail]Error opening file: no such file or directory:

~/bin/hdc shell 'mkdir -p /data/local/codes'

Then copy the files (from your PC):

cd "/home/mav/Documents/Extra/ROS Comp/semi"
for f in *.py *.launch spark; do ~/bin/hdc file send "$PWD/$f" "/data/local/codes/$f"; done

~/bin/hdc is the Linux hdc from the OpenHarmony 5.0.0 SDK. It needs the udev rule /etc/udev/rules.d/50-hdc.rules (SUBSYSTEM=="usb", ATTRS{idVendor}=="2207", MODE="0666") and ~/bin/libusb_shared.so next to it. Check with ~/bin/hdc list targets; the device appears as 2207:5000 Rockchip "HDC Device".

3. Terminal 1 - ON THE SPARK (server: master + base + arm)

ssh root@<robot-ip>

Once on the board:

run roslaunch /data/local/codes/server.launch

This starts rosmaster, spark_base_node, swiftpro_write_node and swiftpro_rviz_node. It does not start the camera or the lidar.

Leave this terminal open. Closing it stops the master and every driver.

Alternative - detached (survives logout / Wi-Fi drop)

run nohup setsid roslaunch /data/local/codes/server.launch \
  > /data/local/codes/server.log 2>&1 < /dev/null &

Check it came up:

run rosnode list

4. Terminal 2 - ON THE SPARK (run your program)

Open a second SSH window to the board, then run exactly one script:

# arm only (attaches motors, resumes last pose)
run python3 /data/local/codes/arm.py

# base only
run python3 /data/local/codes/body.py

# base + arm + pump
run python3 /data/local/codes/key_fullbody.py

Plain python3 will not find rospy - run is mandatory. If your shell reports run: inaccessible or not found, use the full path /system/bin/run ....

Keyboard scripts need a real interactive terminal (they put the TTY in raw mode). Do not start them detached or with output redirected. Do not run two teleop scripts at once.

5. Verify

run rosnode list                        # spark_base_server, swiftpro_write_node, swiftpro_rviz_node
run rostopic hz /SwiftproState_topic    # ~20 Hz after the arm has been commanded
run rostopic info /cmd_vel              # base subscriber present

The arm publishes /SwiftproState_topic only after it receives a command, so a silent topic while idle is normal. If the arm accepts keys but never moves, press A: the motors are detached at power-on and the script re-sends the attach sequence.

Devices on the board:

ls -l /dev/ttyACM0     # arm (swiftpro) - must exist
ls -l /dev/sparkBase   # base - symlink to ttyUSB0

6. Stop

# in the teleop window: Ctrl+C

# stop the server:
run pkill -f server.launch

# or, if you started it detached, the same command works; check with:
run ps -ef | grep roslaunch

Camera / lidar scripts

blue_detect.py, camera_stream.py, blue_view.py and touch_blue.py need the camera, which server.launch does not start. Check the available launches first:

run rospack find spark_bringup
run ls /data/local/release/usr/share/spark_bringup/launch

Then start the bringup instead of server.launch and run the script in a second terminal as above.

For the full competition stack

The vendor stack (base, arm, camera, lidar, detection, grasp, rviz, VNC) is started by the menu script, not by server.launch:

cd /data/local/release
./onekey.sh        # choose the semi-auto option in the menu

Use server.launch when you only need base + arm for an arm/teleop test.
