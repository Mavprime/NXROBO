## 2. Аппаратный комплекс и спецификация робота

Робот представляет собой колесный мобильный манипулятор **NXROBO Spark / Spark-H**:

```text
                          ┌────────────────────────┐
                          │   Intel RealSense      │
                          │   D435 RGB-D Камера    │
                          └───────────┬────────────┘
                                      │
     ┌──────────────────────┐         │          ┌──────────────────────┐
     │   YDLidar G6         │         ▼          │   uArm Swift Pro     │
     │   2D Лазерный лидар  │   ┌────────────┐   │   4-DOF Манипулятор  │
     │   (360°, /scan)      │   │ Intel NUC  │──▶│   + Вакуумная помпа  │
     └──────────────────────┘   │ Ubuntu20.04│   │   (/dev/ttyACM0)     │
                                │ ROS Noetic │   └──────────────────────┘
     ┌──────────────────────┐   └─────┬──────┘
     │  Дифференциальное    │         │          ┌──────────────────────┐
     │  колёсное шасси      │◀────────┴─────────▶│   spark-HM-PI        │
     │  (Spark Base + IR)   │                    │   Плата OpenHarmony  │
     └──────────────────────┘                    └──────────────────────┘
```

1. **Бортовой вычислитель (Main Brain):**
   - Компьютер **Intel NUC** под управлением **Ubuntu 20.04.5 LTS**, **ROS Noetic**.
   - Рабочие директории на роботе:
     - Основные скрипты и утилиты: `/home/spark/codes/`
     - Catkin workspace: `/home/spark/spark_noetic/`
     - Узел соревнований: `/home/spark/spark_noetic/src/3rd_app/auto_match_25/auto_match/`
     - Логи и bag-файлы: `/home/spark/logs/` (включая `/home/spark/logs/bags/`)

2. **Колесная мобильная платформа (Chassis Base):**
   - Дифференциальный колесный привод с энкодерами.
   - Контроллер подключен по внутреннему UART/USB `/dev/sparkBase` (baudrate 115200).
   - Драйвер: `spark_base_server` (топик управления скоростью `/cmd_vel`, тип `geometry_msgs/Twist`).
   - 3 ИК-бампера защиты от падения (`/spark_base/sensor`).
   - *Аппаратная особенность:* канал `ir_bumper_front` постоянно считывается `True` (залипший датчик). Движению колес это не мешает.

3. **Манипулятор (Robotic Arm):**
   - 4-осевой манипулятор **uArm Swift Pro** (`swiftpro`) на шаговых двигателях без энкодеров усилия.
   - Подключение: плата Arduino Mega 2560 по USB-Serial (`/dev/ttyACM0`), протокол G-кода Marlin (`G0 X... Y... Z...`).
   - Топики:
     - `/position_write_topic` (`swiftpro/position`): целевые координаты конца манипулятора ($X, Y, Z$ в мм).
     - `/SwiftproState_topic` (`swiftpro/SwiftproState`): телеметрия фактического положения руки и помпы (20 Гц).
     - `/swiftpro_status_topic` (`swiftpro/status`): питание шаговиков (M17 — удержание, M2019 — расслабление).
   - Рабочие лимиты руки: $X \in [90, 320]$ мм, $Y \in [-160, 160]$ мм (до $\pm 195$ мм), $Z \in [-85, 180]$ мм.
   - Зона комфортного прямого захвата (sweet-spot): $X \in [160, 265]$ мм, $|Y| \le 85$ мм, $R \le 270$ мм.
   - Домашняя/сервисная поза (Tuck): $X = 50, Y = 180, Z = 160$ мм. Рука отводится вбок, освобождая поле зрения лидара и камеры. **При сканировании рука обязана быть в этой позе!**

4. **Захватный орган (End-Effector / Suction Gripper):**
   - Силиконовая вакуумная присоска с пневмокомпрессором и электромагнитным стравливающим клапаном.
   - Управление помпой: `/pump_topic` (`swiftpro/status`: 1 — включить всасывание, 0 — сбросить вакуум).
   - Аппаратное смещение центра присоски: $+20$ мм по оси $X$ вперед относительно оптического центра оранжевого пятна присоски (`fix_dx = 20.0`).

5. **Оптическая система зрения (Vision Sensor):**
   - Стереокамера **Intel RealSense D435**.
   - RGB-поток: `/camera/color/image_raw` (640×480, 30 FPS).
   - Облако точек: `/camera/depth_registered/points`.
   - Видеотрансляция: HTTP MJPEG веб-сервер `camera_stream.py` на порту `8080`.
   - *Особенность глубины:* датчик глубины искажает расстояние на дистанциях ближе 0.5 м. Расчет координат кубиков переведен на аналитическую 3D-проекцию DLT, без использования сырой глубины камеры.

6. **Лазерный дальномер (LiDAR Sensor):**
   - 2D круговой лидар **YDLidar G6** (порт `/dev/ydlidar` или `/dev/ttyUSB0`).
   - Топик: `/scan` (360°, частота 10 Гц). Запускается автоматически в `start_system.sh`.

7. **Плата HarmonyOS (spark-HM-PI):**
   - Плата под управлением OpenHarmony 3.1.6 (`/dev/SPARK-HM-PI`). Служит мостом для смартфона и внешних ворот полигона (для трека полуавтомата).

## 4. Регламент матча и стратегия набора очков

- **Время заезда:** Ровно **10 минут** (600 секунд). Вмешательство оператора запрещено.
- **Внутренний таймер робота:** `MatchClock` настроен на бюджет **540 секунд** (9 минут). Робот плавно сворачивает миссию до истечения 600 с, избегая штрафа за овертайм.
- **Полигон:** Арена 3 × 3 м. 4 зоны по углам ($A, B, C, D$).
- **Кубики (всего 10 шт):**
  - **1 × Торт (Cake, ID 2 / 20)** — 2-й ярус тумбы в центре ($Z = +50$ мм).
  - **3 × Мишка (ID 1 / 10)** — 1-й этаж на полу ($Z = -50$ мм).
  - **3 × Часы (ID 3 / 30)** — 1-й этаж на полу ($Z = -50$ мм).
  - **3 × Банан (ID 4 / 40)** — 1-й этаж на полу ($Z = -50$ мм).

### ⚠️ КРИТИЧЕСКОЕ ПРАВИЛО:
> **Торт со 2-го яруса ОБЯЗАН быть доставлен в Зону A ПЕРВЫМ.**  
> Если первым доставлен любой другой кубик, очки за торт полностью аннулируются. В `runtask.py` зафиксировано: самый первый захват на `total_drop_times == 0` жестко направлен на `CAKE_SORTING_STATION` (`Sorting_M`), захват методом `grasp1()`, а доставка — в `Collection_A`.

### Начисление баллов:
1. Выезд со старта: **+1 балл**.
2. **Красный квадрат приёмки (Зона A, 0.45 × 0.45 м):**
   - 1-й ярус: **2 балла**
   - 2-й ярус (стекинг): **4 балла**
   - 3-й ярус (башня): **7 баллов**
   - Формула: $\mathbf{Score = N + 2^{N-1}}$
3. **Обычные зоны транспортировки (B, C, D):**
   - 1-й ярус = **1 балл**, 2-й ярус = **2 балла**, 3-й ярус = **4 балла** (формула: $2^{N-1}$).
4. **Штрафы:**
   - Фальстарт: $-6$ баллов.
   - Овертайм: $-2$ балла/сек.
   - Поворот кисти присоски: $-5$ баллов.

## 8. Справочник ключевых топиков ROS, параметров и калибровок

### Топики ROS:
| Топик | Тип сообщения | Описание и назначение |
|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | Управление линейной ($v_x$) и угловой ($\omega_z$) скоростью шасси |
| `/camera/color/image_raw` | `sensor_msgs/Image` | Видеопоток RGB RealSense D435 ($640 \times 480$, 30 FPS) |
| `/scan` | `sensor_msgs/LaserScan` | Круговой скан лидара YDLidar G6 (частота 10 Гц) |
| `/objects` | `vision_msgs/Detection2DArray` | Распознанные кубики от YOLO детектора (дедуплицированные) |
| `/position_write_topic` | `swiftpro/position` | Команда целевых координат руки ($X, Y, Z$ в мм) |
| `/SwiftproState_topic` | `swiftpro/SwiftproState` | Телеметрия руки (фактические $X, Y, Z$, углы сервоприводов, помпа) |
| `/pump_topic` | `swiftpro/status` | Управление вакуумной помпой (`1` — вкл, `0` — выкл) |
| `/spark_base/sensor` | `spark_base/SparkBaseSensor` | Данные бамперов и напряжение бортового аккумулятора |
| `/task_start_flag` | `std_msgs/String` | Запуск/остановка миссии оператором (`start` / `stop`) |
| `/grasp` | `std_msgs/String` | Ручной тест захвата (`'1'` — взять куб, `'0'` — отпустить) |
| `/move_base/status` | `actionlib_msgs/GoalStatusArray` | Статус готовности и выполнения навигационных целей |
| `mark_nav` | `std_msgs/String` | Команды навигации по именованным точкам (`go <имя>` / `arrive <имя>`) |

### Ключевые параметры захвата и высот:
- **Матрица проекции DLT:** файл `/home/spark/codes/transform_3d.dat`.
- **Высоты касания ($Z_{touch}$):**
  - Кубы на полу (1-й ярус): $Z_{touch} = -50.0$ мм, $Z_{center} = -100.0$ мм.
  - Торт на тумбе (2-й ярус): $Z_{touch} = +50.0$ мм, $Z_{center} = 0.0$ мм.
- **Безопасные высоты пролета руки:**
  - Над кубами 1-го яруса: $Z_{above} = -15.0$ мм.
  - Пролет над препятствиями при взятии торта: $Z_{safe} = +100.0$ мм.
- **Высота подъема с кубиком:** $Z_{lift} = +60.0$ мм.
- **Безопасный вертикальный отвод при сбросе:** $+80.0$ мм вверх перед складыванием руки вбок.
- **Поправка чашки присоски:** `fix_dx = +20.0` мм.
- **Зона прямого захвата (sweet-spot):** $X \in [160, 265]$ мм, $|Y| \le 85$ мм, $R \le 270$ мм.
- **Высоты стекинга при сдаче кубиков:**
  - 1-й этаж: $Z = -55.0$ мм (`drop()`)
  - 2-й этаж: $Z = +60.0$ мм (`drop1()`)
  - 3-й этаж: $Z = +160.0$ мм (`drop2()`)

## 9. Операционный регламент: как запускать робота

### Быстрый запуск с рабочего ПК оператора (Windows):
1. Включить питание робота тумблером, дождаться загрузки NUC (~30 с).
2. На компьютере дважды кликнуть по **`START_ROBOT.bat`** в папке `auto\launchers\` (или запустить `connect.ps1`).
3. Подтвердить сохраненный IP (`Enter`) или ввести новый.
4. Откроется окно дашборда на роботе:

```text
================================================================
           SPARK AUTONOMOUS ROBOT: CONTROL DASHBOARD            
================================================================
  1) START ALL SYSTEMS          -> Фоновый запуск драйверов, детектора, runtask и bag
  2) TEST CUBE GRASP            -> Тест захвата кубика на месте (/grasp 1)
  3) TEST CUBE RELEASE          -> Тест отпускания кубика (/grasp 0)
  4) SMOOTH KEYBOARD TELEOP     -> Плавное ручное управление (WASD + рука)
  5) VIEW LIVE RUNTASK LOG      -> Просмотр лога соревнований (выход по 'q')
  6) STOP ALL SYSTEMS           -> Безопасная остановка всех процессов
  7) DIAGNOSTICS & SYSTEM TEST  -> Полная проверка сенсоров, топиков и калибровок
  8) VIEW DETECTOR LOG          -> Логи детектора YOLO
  9) MISSION BAGS               -> Список ~/logs/bags + закрыть запись
  0) Exit to bash               -> Выход в консоль Ubuntu
================================================================
```

### Запуск соревновательного матча:
1. Выбрать пункт **`1`** (Запустить все системы).
2. Открыть в браузере `http://<IP_робота>:8080/`, проверить картинку с камеры.
3. Поставить робота на стартовую позицию.
4. Подать команду старта в терминале:
   ```bash
   rostopic pub /task_start_flag std_msgs/String "data: 'start'" --once
   ```
5. Для аварийной остановки заезда:
   ```bash
   rostopic pub /task_start_flag std_msgs/String "data: 'stop'" --once
   ```
