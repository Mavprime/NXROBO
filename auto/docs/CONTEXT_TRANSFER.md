## 2. Описание робота, его частей и аппаратного комплекса

Робот представляет собой автономный мобильный манипулятор **NXROBO Spark / Spark-H**, предназначенный для соревнований по регламенту *«夺宝奇兵自动赛»* (Treasure Hunt / Полный автоном) и *M-Robots OS*:

```
                          ┌────────────────────────┐
                          │   Intel RealSense      │
                          │   D435 RGB-D Камера    │
                          └───────────┬────────────┘
                                      │
     ┌──────────────────────┐         │          ┌──────────────────────┐
     │   YDLidar G6         │         ▼          │   uArm Swift Pro     │
     │   2D Лазерный лидар  │   ┌────────────┐   │   4-DOF Манипулятор  │
     │   (360°, /scan)      │   │ Intel NUC  │──▶│   + Вакуумная помпа  │
     └──────────────────────┘   │ Ubuntu20.04│   │   (/dev/ttyACM0)     │
                                │ ROS Noetic │   └──────────────────────┘
     ┌──────────────────────┐   └─────┬──────┘
     │  Дифференциальное    │         │          ┌──────────────────────┐
     │  колёсное шасси      │◀────────┴─────────▶│   spark-HM-PI        │
     │  (Spark Base + IR)   │                    │   Плата OpenHarmony  │
     └──────────────────────┘                    └──────────────────────┘
```

### Детальная спецификация компонентов:
1. **Бортовой вычислитель (Main Brain):**
   - Компьютер **Intel NUC** под управлением **Ubuntu 20.04.5 LTS**.
   - Стек промежуточного ПО: **ROS Noetic Ninjemys**.
   - Рабочие директории:
     - Основной catkin workspace: `/home/spark/spark_noetic`
     - Соревновательный пакет: `/home/spark/spark_noetic/src/3rd_app/auto_match_25/auto_match/`
     - Пользовательские скрипты управления: `/home/spark/codes/`
     - Релиз полуавтомата: `/data/local/release`

2. **Колесная мобильная платформа (Chassis Base):**
   - Дифференциальный колесный привод с энкодерами и токовыми защитами.
   - Встроенный контроллер шасси подключен по внутреннему UART/USB (`/dev/sparkBase`, baudrate 115200).
   - Драйвер: `spark_base_server` (принимает команды скорости `geometry_msgs/Twist` в топик `/cmd_vel`).
   - Датчики безопасности: 3 инфракрасных бампера защиты от падения со ступеней и препятствий (`/spark_base/sensor`).

3. **Манипулятор (Robotic Arm):**
   - 4-осевой рычажный манипулятор **uArm Swift Pro** (`swiftpro`).
   - Управляется собственной платой Arduino Mega 2560 по USB-Serial (`/dev/ttyACM0`), прошивка интерпретирует протокол G-кода Marlin (`G0 X... Y... Z... F...`).
   - Топики ROS:
     - `/position_write_topic` (`swiftpro/position`): абсолютные координаты $(X, Y, Z)$ концевой точки в миллиметрах.
     - `/SwiftproState_topic` (`swiftpro/SwiftproState`): телеметрия текущего положения.
     - `/swiftpro_status_topic` (`swiftpro/status`): активация питания шаговых двигателей (команда M17).
   - Безопасная рабочая зона руки:
     - $X \in [90, 320]$ мм
     - $Y \in [-160, 160]$ мм (до $\pm 195$ мм в расширенном режиме)
     - $Z \in [-85, 180]$ мм
   - Домашняя/сервисная поза парковки (Home/Tuck): $X = 50, Y = 180, Z = 160$ мм (убирает руку в сторону, полностью освобождая поле зрения лидара и камеры).

4. **Захватный орган (End-Effector / Gripper):**
   - Вакуумная силиконовая присоска, соединенная пневматическим шлангом с компрессором и электромагнитным стравливающим клапаном.
   - Управление помпой: топик `/pump_topic` (`swiftpro/status`): `1` — включить всасывание, `0` — сбросить вакуум.
   - Координация захвата: топик `/grasp_status` (`std_msgs/String`).

5. **Оптическая система зрения (Vision Sensor):**
   - Глубинная стереокамера **Intel RealSense D435**.
   - RGB-поток: `/camera/color/image_raw` (разрешение $640 \times 480$, 30 FPS).
   - Стриминг: MJPEG HTTP веб-сервер `camera_stream.py` на порту `8080`.

6. **Лазерный дальномер (LiDAR Sensor):**
   - 2D круговой лидар **YDLidar G6** (порт `/dev/ydlidar` или `/dev/ttyUSB0`).
   - Топик: `/scan` (`sensor_msgs/LaserScan`), круговой обзор 360°, частота 10–12 Гц, радиус действия до 25 метров.
   - Используется для построения карты (`gmapping`) и локализации (`amcl` / `move_base`).

7. **Дополнительная коммуникационная плата (HarmonyOS Bridge):**
   - Плата **spark-HM-PI** под управлением **OpenHarmony 3.1.6**, подключенная по USB-CDC (`/dev/SPARK-HM-PI`).
   - Отвечает за прием команд управления с приложения HarmonyOS, NFC-метки и связь с внешними воротами полигона (`/hm_task_gate_cmd`).

### Компьютерное зрение и физический захват (Фаза 1 — 100%):
- [x] **Полноценный захват и подъем кубика на реальном роботе:** Робот захватывает кубики на полу и на 2-м ярусе тумбы, уверенно поднимает их, переносит и сбрасывает в заданную зону.
- [x] **Temporal Voting + Spatial Clustering (реализовано по-настоящему):** `CamAction.detector()` собирает окно из `GRASP_FRAMES = 4` кадров **после момента вызова** (важно после доворота шасси), а `match_logic.cluster_detections()` объединяет рамки в радиусе 45 px, усредняет центр и выбирает класс большинством голосов. Раньше в проде этого не было — был один кадр; тесты же проверяли копию логики внутри тестового файла.
- [x] **Дедупликация двух нейросетей:** `detect_ros.py` запускает две модели (`auto.pt` + `banana.pt`), и до 19.11 один кубик мог попасть в `/objects` дважды. Теперь `match_logic.dedupe_boxes()` (60 px, один класс) публикует один кубик = одна запись. TTA (`augment=True`) по умолчанию выключен: он втрое замедляет инференс на NUC.
- [x] **Нормализатор классов (`norm_id`):** Приведение алиасов (`1`, `2/10/20`, `3/30`, `40`) к каноническим ID соревнований:
  - `1` $\to$ Мишка (Teddy Bear)
  - `2` $\to$ Торт (Cake)
  - `3` $\to$ Часы (Clock)
  - `4` $\to$ Банан (Banana)
- [x] **Заводские файлы калибровки сохранены и проверены:**
  - `~/thefile.txt` (1-й ярус на полу)
  - `~/thefile2.txt` (2-й ярус тумбы / торт)
  - Высоты больше НЕ хардкодятся: `target_from_pixel()` берёт измеренную глубиной поверхность и считает `z_hover / z_touch / z_lift` от неё (`contact_heights()`), с полом `SAFE_MIN_Z = -120` мм.
- [x] **Прямой захват на месте (In-Place Grasp):** Если обнаруженный кубик попадает в полусферу досягаемости руки, колесная база **НЕ двигается**, манипулятор берет кубик сразу с текущей позиции.
- [x] **Visual Servoing и защита от толкания:** Если кубик сбоку или далеко, база доворачивает на месте. Движение вперед блокируется, если кубик ближе 295 мм ($X \le 295$), что исключает удар бампера по кубику.
- [x] **Повторное сканирование (Re-scan после маневра):** После доворота база делает паузу 0.20 с для гашения вибраций, проводит **свежее** сканирование (окно кадров начинается после поворота) и пересчитывает координаты в новом ракурсе с сохранением исходного класса цели.
- [x] **Ступенчатое перемещение руки (`move_z_steps`):** Защита от пропуска шагов! Вертикальное опускание и подъем разбиваются на 4 мелких шага с задержками (0.6 с).
- [x] **Безопасный вертикальный отвод при сбросе (+80 мм):** При отпускании кубика вакуум стравливается (0.25 с), присоска поднимается строго вертикально на +80 мм и только затем рука складывается вбок.
- [x] **Кинематическая модель досягаемости — один экземпляр:** математика IK живёт в `match_logic.py` (`ik_reachable`, `pixel_to_arm`, `pixel_reachable`), `arm_ik.py` — тонкий совместимый шим, `runtask.py` импортирует её. Раньше в `runtask.py` лежала приватная копия, а тест проверял `arm_ik.py`, то есть не тот код.

### Соревновательный автомат FSM (Фаза 3 — код готов, на арене не проверен):
- [x] **Жесткое соблюдение правила Первого Торта:** На старте заезда робот идёт на `CAKE_SORTING_STATION` (по умолчанию `Sorting_M`), вызывает `grasp1()` и везёт добычу в Зону A. **Новое:** после захвата проверяется класс — если схвачен не торт, это пишется в лог как потеря очков за торт, но миссия продолжается (раньше «торт первым» держался только на позиции, а любой кубик в кадре мог быть схвачен).
- [x] **Считывание доски классификации:** слоты доски считываются серией кадров и голосуются, результат отдаётся в `match_logic.decode_classification_board()`, который **всегда** возвращает полный маппинг (SI-14: при сбое доски/навигации берётся `DEFAULT_MAPPING`, миссия не останавливается).
- [x] **Часы матча:** `match_logic.MatchClock` с бюджетом `TASK_TIME_BUDGET_S = 540` с (600 с матча минус запас). Часы проверяются перед каждой станцией и перед захватом; при истечении робот аккуратно завершает заезд вместо овертайма (−2 балла/сек).
- [x] **Разбор payload `/task_start_flag`:** `start|1|go|on|true` запускают заезд, `stop|0|halt|off|abort` останавливают, всё остальное игнорируется с предупреждением. Раньше **любое** сообщение (включая `stop`) запускало миссию.
- [x] **Планирование зон и ярусов вынесено в чистые функции:** `choose_drop_zone()` (маппинг → свободная зона, `None` если все зоны заполнены), `plan_drop()` (1/2/3 ярус, отказ на 4-м), `choose_station()` (предпочтение ближней станции), `approach_waypoint()` / `exit_maneuver()` (манёвры у станций), `retire_station()`.
- [x] **Логика матча тестируема без ROS:** `match_logic.py` не импортирует rospy; 90 unit-тестов проверяют именно его (и через wiring-тесты — что `runtask.py`/`detect_ros.py` действительно его вызывают).
- [x] **Диагностический комплекс:** [`test_all_systems.py`](file:///d:/ROS%20competition/spark_humble_ws/codes/test_all_systems.py) проверяет калибровки, процессы, порты, стрим :8080, топики (`/scan`, камера, бамперы, **`/objects`**) и готовность к автономному заезду: `move_base`, `mark_map.pkl`, запись bag, наличие `~/transform_3d.dat`.

## 6. Регламент соревнований и стратегия набора очков

Соревнование: **«夺宝奇兵自动赛» (Автономная миссия «Охота за сокровищами»)**.

### Основные правила:
- **Время заезда:** **10 минут** чистого времени.
- **Вмешательство оператора:** **Строго запрещено** после стартового свистка. Любое касание ПК или робота карается штрафом или дисквалификацией.
- **Право на рестарт:** Разрешено до 3 перезапусков **только до момента отрыва первого кубика от земли**.
- **Всего кубиков:** 10 штук.
  - **1 × Торт (Cake)** — расположен в центре на **2-м ярусе** тумбы ($Z = 45$ мм).
  - **3 × Мишка (Bear)** — 1-й ярус.
  - **3 × Часы (Clock)** — 1-й ярус.
  - **3 × Банан (Banana)** — 1-й ярус.

### КРИТИЧЕСКОЕ ПРАВИЛО ПЕРВОГО КУБИКА:
> **Торт со 2-го яруса ОБЯЗАН быть доставлен в Зону A ПЕРВЫМ.**  
> Если робот первым захватит и доставит любой другой кубик, очки за торт **полностью аннулируются**. В логике `runtask.py` это правило аппаратно зафиксировано на `total_drop_times == 0`.

### Система начисления баллов:
1. **Старт со стартовой позиции:** **+1 балл**.
2. **Зоны сдачи кубиков (Collection Zones):**
   - **Красный квадрат приёмки (0.45 × 0.45 м):**
     - 1-й этаж (на полу): **2 балла**
     - 2-й этаж (стекинг поверх другого кубика): **4 балла**
     - 3-й этаж (третий ярус башни): **7 баллов**
     - *Формула красной зоны:* $\mathbf{Score = N + 2^{N-1}}$
   - **Обычная зона пола:**
     - 1-й этаж = **1 балл**, 2-й этаж = **2 балла**, 3-й этаж = **4 балла** (формула: $2^{N-1}$).
3. **Штрафы:**
   - Фальстарт: $-6$ баллов.
   - Задержка времени (овертайм): $-2$ балла/сек.
   - Программный поворот присоски (wrist rotation): $-5$ баллов.

## 9. Справочник ключевых топиков ROS и калибровок

### Топики ROS:
| Топик | Тип сообщения | Назначение |
|---|---|---|
| `/cmd_vel` | `geometry_msgs/Twist` | Управление скоростью колес ($v_x, \omega_z$) |
| `/camera/color/image_raw` | `sensor_msgs/Image` | Необработанный RGB видеопоток RealSense D435 |
| `/camera/depth_registered/points` | `sensor_msgs/PointCloud2` | Облако точек; `point3d()` тянет один кадр по требованию |
| `/scan` | `sensor_msgs/LaserScan` | 360° лазерное сканирование лидара YDLidar G6 |
| `/objects` | `vision_msgs/Detection2DArray` | Распознанные YOLO объекты (уже без дублей двух моделей) |
| `/debug_image` | `sensor_msgs/Image` | Кадр с нарисованными рамками для отладки |
| `/position_write_topic` | `swiftpro/position` | Команда целевых координат руки ($X, Y, Z$ в мм) |
| `/pump_topic` | `swiftpro/status` | Управление вакуумной помпой (`1` = вкл, `0` = выкл) |
| `/SwiftproState_topic` | `swiftpro/SwiftproState` | Текущие углы и координаты uArm |
| `/spark_base/sensor` | `spark_base/SparkBaseSensor` | Данные бамперов и напряжение батареи |

| `/move_base/status`, `/move_base/result` | `actionlib_msgs` | Готовность и результат навигации (нужен запущенный `move_base`) |
| `mark_nav` | `std_msgs/String` | Команды `go <точка>` / `arrive <точка>` для узла навигации |

### Параметры калибровки руки и высот:
- **Преобразование пикселей в координаты руки:**
  $$\begin{cases} X_{arm} = k_1 \cdot \text{row} + b_1 \\ Y_{arm} = k_2 \cdot \text{col} + b_2 \end{cases}$$
  *(Строка матрицы пикселей задает $X$, столбец задает $Y$; коэффициенты — в `~/thefile.txt` / `~/thefile2.txt`)*.
- **Основной путь — по глубине:** `CamAction.target_from_pixel()` берёт 3D-точку из `/camera/depth_registered/points`, переводит её в координаты руки калибровочной матрицей `TRANSFORM_3D` (или `~/transform_3d.dat`, если файл есть) и принимает результат, только если высота правдоподобна для нужного яруса. Если глубина не дала валидной точки — пиксель проецируется на известную высоту яруса (`pixel_to_arm_at_z`), затем 2D-калибровка как последний резерв.
- **Высоты НЕ фиксированы в коде, а считаются от поверхности** (`contact_heights()`):
  - $Z_{hover} = Z_{surface} + 45$ мм
  - $Z_{touch} = \max(Z_{surface} + 8, -120)$ мм — 8 мм учитывают толщину присоски (`PAD_THICKNESS_MM`)
  - $Z_{lift} = \min(Z_{surface} + 100, 165)$ мм
  - Время выдержки вакуума: 0.50 с перед подъёмом
- **Высоты стекинга при сдаче в зону (фиксированные, от яруса):**
  - Ярус 1: $Z = -55$ мм (`drop()`), точка $(235, 0)$
  - Ярус 2: $Z = 60$ мм (`drop1()`), X/Y по видимому кубику в зоне
  - Ярус 3: $Z = 160$ мм (`drop2()`), X/Y по видимому кубику в зоне
  - Если зона уже держит 3 кубика, `choose_drop_zone()` уводит кубик в свободную зону, а не сбрасывает его в пустоту.
