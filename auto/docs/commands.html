Spark Robot - Quick Commands

One command now starts whatever the script needs. You no longer keep a server terminal open and open a second terminal for the script: ~/semi/spark starts the ROS stack once in the background (detached, survives logout) and reuses it on later runs.

1. Which robot, which folder

Local folderWhat it isWhere it runs on the robot
semi/Manual / teleop scripts (arm, body, keyboard, blue-box tools)~/semi/
auto/Full-auto release (FSM, detector, dashboard, logs)~/semi/ + ~/spark_noetic/src/3rd_app/auto_match_25/auto_match/nodes/
Manuals/Rules, configuration, competition material packsPC only

This document is for the Ubuntu Spark (user spark, password simple2026, ROS Noetic in ~/spark_noetic).

The M-Robots / OpenHarmony board is a different machine: user root, password 123456, code in /data/local/codes, and every ROS command needs the run wrapper. Use semi/docs/spark_semi.html for that board.

2. Run any script in ONE terminal

~/semi/spark <script>.py

The wrapper source-loads the ROS environment, starts ~/semi/server.launch (base + uArm) if the master is not up, then runs the script. Later runs see the master already running and start nothing twice.

CommandWhat it does
~/semi/spark key_fullbody.pyKeyboard drive: base + arm + pump
~/semi/spark arm.pyArm-only keyboard teleop
~/semi/spark body.pyBase-only keyboard teleop
~/semi/spark arm_move.py --homeMove the arm to an absolute pose
~/semi/spark pump_test.pyVacuum pump on/off test
~/semi/spark --camera blue_detect.pyBlue-box detector (needs the camera)
~/semi/spark --camera touch_blue.pyCamera + arm: touch the top of the blue box
~/semi/spark --camera camera_stream.pyWeb stream on http://<robot-ip>:8080/
~/semi/spark --statusShow the running ROS nodes
~/semi/spark --stopStop the base / camera / arm launches

--camera starts the full bringup instead of server.launch:

roslaunch spark_bringup driver_bringup.launch camera_type_tel:=d435 lidar_type_tel:=ydlidar_g6
roslaunch swiftpro pro_control_nomoveit.launch

i.e. base + RealSense D435 + YDLidar + uArm. If a stack without the camera is already running, the wrapper refuses and tells you to run ~/semi/spark --stop first — that is deliberate, starting a second base driver on the same serial port only produces errors.

Log: the detached stack writes to ~/server.log. Follow it with tail -f ~/server.log. The wrapper waits until the master (and, with --camera, the camera topic) is actually up before it starts your script.

3. Full-auto match in one command

~/semi/start_system.sh

Starts everything in the background: base, RealSense, lidar, uArm, web stream, YOLO detector and runtask.py. Logs go to ~/logs/ (base.log, arm.log, detect.log, runtask.log, stream.log).

# start the task
rostopic pub -1 /task_start_flag std_msgs/String "1"

# abort the task
rostopic pub -1 /task_start_flag std_msgs/String "0"

# stop every subsystem
~/semi/stop_system.sh

Prefer a menu? ~/semi/dashboard.sh gives you options 1-7 (start, grasp test, release test, teleop, live log, stop). On Windows, START_ROBOT.bat connects and opens it for you.

4. Copy code to the robot (from your PC)

Manual scripts → ~/semi:

rsync -av --exclude='__pycache__/' semi/ spark@<robot-ip>:~/semi/

Full-auto nodes → the ROS package, everything else → ~/semi (this is what upload.ps1 does on Windows):

scp auto/codes/runtask.py auto/codes/detect_ros.py \
    spark@<robot-ip>:~/spark_noetic/src/3rd_app/auto_match_25/auto_match/nodes/

rsync -av auto/codes/ spark@<robot-ip>:~/semi/

Keep the trailing slash on the source: it copies the folder's contents; without it you get a nested semi/semi.

No rsync on the PC? Use scp -r "<local-dir>" <user>@<robot-ip>:<remote-dir>.

5. Fallback: manual two-terminal start

Use this only if ~/semi/spark is missing or fails (e.g. you copied only a few files).

# Terminal 1 - keep it open
source ~/spark_noetic/devel/setup.bash
roslaunch ~/semi/server.launch

# Terminal 2
source ~/spark_noetic/devel/setup.bash
python3 ~/semi/<script>.py

Keep terminal 1 running; closing it stops the master and every driver. To detach it instead:

setsid nohup roslaunch ~/semi/server.launch > ~/server.log 2>&1 < /dev/null &

6. Before you run anything

ls -l /dev/sparkBase      # base serial
ls -l /dev/ttyACM*        # arm serial (expect /dev/ttyACM0)

If the arm device is missing, reconnect or power it. Without /dev/ttyACM0 the arm driver reports Unable to open port.

7. Verify

~/semi/spark --status                 # nodes: /spark_base_server, /swiftpro_write_node
rostopic hz /SwiftproState_topic      # arm: about 20 Hz
rostopic info /cmd_vel                # base: one subscriber
rostopic list | grep camera           # camera topics (only with --camera)
