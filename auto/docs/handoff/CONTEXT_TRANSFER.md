## 2. Аппаратный комплекс и спецификация робота

Робот — колёсный мобильный манипулятор **NXROBO Spark / Spark-H**:

```text
                          ┌────────────────────────┐
                          │   Intel RealSense      │
                          │   D435 RGB-D Камера    │
                          └───────────┬────────────┘
                                      │
     ┌──────────────────────┐         │          ┌──────────────────────┐
     │   YDLidar G6         │         ▼          │   uArm Swift Pro     │
     │   2D Лазерный лидар  │   ┌────────────┐   │   4-DOF Манипулятор  │
     │   (360°, /scan)      │   │ Intel NUC  │──▶│   + Вакуумная помпа  │
     └──────────────────────┘   │ Ubuntu20.04│   │   (/dev/ttyACM0)     │
                                │ ROS Noetic │   └──────────────────────┘
     ┌──────────────────────┐   └─────┬──────┘
     │  Дифференциальное    │         │          ┌──────────────────────┐
     │  колёсное шасси      │◀────────┴─────────▶│   spark-HM-PI        │
     │  (Spark Base + IR)   │                    │   Плата OpenHarmony  │
     └──────────────────────┘                    └──────────────────────┘
```

1. **Бортовой вычислитель (Main Brain):**
   - **Intel NUC**, **Ubuntu 20.04.5 LTS**, **ROS Noetic**.
   - Рабочие директории на роботе:
     - Основные скрипты и утилиты: `/home/spark/codes/`
     - Catkin workspace: `/home/spark/spark_noetic/`
     - Узел соревнований: `/home/spark/spark_noetic/src/3rd_app/auto_match_25/auto_match/nodes/`
     - Логи и bag-файлы: `/home/spark/logs/` (включая `/home/spark/logs/bags/`)
     - Калибровки: `/home/spark/transform_3d.dat`, `/home/spark/transform_3d.meta.json`, `/home/spark/thefile2.txt`

2. **Колёсная мобильная платформа (Chassis Base):**
   - Дифференциальный привод с энкодерами.
   - Контроллер: `/dev/sparkBase` (baudrate 115200), драйвер `spark_base_server`.
   - Управление: `/cmd_vel` (`geometry_msgs/Twist`).
   - 3 ИК-бампера (`/spark_base/sensor`).
   - *Аппаратная особенность:* `ir_bumper_front` постоянно читается `True` (залипший датчик). Движению колёс не мешает, но засоряет телеметрию.

3. **Манипулятор (Robotic Arm):**
   - 4-осевой **uArm Swift Pro** (`swiftpro`) на шаговых двигателях без силовой обратной связи.
   - Плата Arduino Mega 2560 по USB-Serial (`/dev/ttyACM0`), протокол G-кода Marlin (`G0 X... Y... Z...`).
   - Топики:
     - `/position_write_topic` (`swiftpro/position`) — целевые координаты конца руки (мм).
     - `/SwiftproState_topic` (`swiftpro/SwiftproState`) — телеметрия (фактически последняя **скомандованная** поза; см. §6).
     - `/pump_topic` (`swiftpro/status`) — помпа.
   - Рабочие лимиты телеопа: $X \in [90, 320]$ мм, $Y \in [-160, 160]$ мм, $Z \in [-85, 180]$ мм.
   - Рабочий конверт полевого захвата 1-го яруса: $X \in [140, 290]$ мм, $|Y| \le 100$ мм, $R \le 295$ мм (цель $R = 240$ мм).
   - Торт 2-го яруса: целевая дистанция **305 мм**, допускается до **355 мм**; `x` клампится на **348 мм** (предел прошивки/кинематики).
   - Сервисная/домашняя поза (Tuck): **$X=50, Y=180, Z=160$ мм**. Рука отводится вбок, освобождая обзор камеры и лидара. **При сканировании рука обязана быть в этой позе.**

4. **Захватный орган (End-Effector / Suction Gripper):**
   - Силиконовая вакуумная присоска + пневмокомпрессор + стравливающий клапан.
   - Управление: `/pump_topic` (`1` — всасывание, `0` — сброс).
   - Пол 1-го яруса: поправка центра чашки **`fix_dx = +20 мм`**.
   - Торт 2-го яруса: выделенная аффинная калибровка `thefile2.txt` + **`cup_offset_x = 125 мм`** (проверено 22.11).
   - Высота касания пола в полевом тесте: `FLOOR_TOUCH_Z = -55`; фактическая команда с прижимом: **-58 мм**.
   - Высота касания торта: состояние `~/logs/cake_smooth_state.json` хранит **40 мм**; команда с прижимом: **37 мм** (fallback по умолчанию 35 → 32 мм).

5. **Оптическая система зрения (Vision Sensor):**
   - **Intel RealSense D435**.
   - RGB: `/camera/color/image_raw` (640×480, 30 FPS).
   - Облако/глубина: `/camera/depth_registered/points`, `/camera/aligned_depth_to_color/image_raw`.
   - Видеотрансляция: HTTP MJPEG `camera_stream.py` на порту **8080**.
   - *Глубина:* датчик нелинейно врёт ближе 0.5 м. В полевом тесте глубина используется только как первая оценка; при сомнении — DLT-проекция (пол) или `pixel_to_cake_xy` (торт).

6. **Лазерный дальномер (LiDAR):**
   - **YDLidar G6** (`/dev/ydlidar` или `/dev/ttyUSB0`), `/scan` (360°, 10 Гц). Запускается в `start_system.sh`.

7. **Плата HarmonyOS (spark-HM-PI):**
   - OpenHarmony 3.1.6 (`/dev/SPARK-HM-PI`), мост для смартфона и внешних ворот (трек полуавтомата).

## 4. Регламент матча и стратегия набора очков

- **Время заезда:** ровно **10 минут** (600 с), вмешательство оператора запрещено.
- **Внутренний таймер:** `MatchClock` на **540 с** (9 минут), чтобы свернуть миссию до овертайма.
- **Полигон:** арена **3 × 3 м**, 4 зоны по углам ($A, B, C, D$), красные квадраты приёмки 0.45 × 0.45 м.
- **Кубики (10 шт):**
  - **1 × Торт (Cake, ID 2 / 20)** — 2-й ярус центральной тумбы ($Z \approx +40$ мм).
  - **3 × Мишка (ID 1 / 10)** — 1-й ярус ($Z \approx -50$ мм).
  - **3 × Часы (ID 3 / 30)** — 1-й ярус.
  - **3 × Банан (ID 4 / 40)** — 1-й ярус.

### ⚠️ КРИТИЧЕСКОЕ ПРАВИЛО

> **Торт со 2-го яруса ОБЯЗАН быть доставлен в Зону A ПЕРВЫМ.**  
> Если первым доставлен любой другой кубик, очки за торт аннулируются.  
> В `runtask.py` первый захват при `total_drop_times == 0` жёстко направлен на `CAKE_SORTING_STATION` (`Sorting_M`), захват — `grasp1()`, доставка — `Collection_A`.  
> **Внимание:** сейчас `grasp1()` содержит устаревшие cake-константы (см. §6.1), поэтому правило программно заявлено, но физически не гарантировано.

### Начисление баллов

1. Выезд со старта: **+1 балл**.
2. **Красный квадрат приёмки (Зона A):**
   - 1-й ярус: **2 балла**
   - 2-й ярус: **4 балла**
   - 3-й ярус: **7 баллов**
   - Формула: $\mathbf{Score = N + 2^{N-1}}$
3. **Обычные зоны (B, C, D):**
   - 1-й ярус = **1 балл**, 2-й = **2 балла**, 3-й = **4 балла** ($2^{N-1}$).
4. **Штрафы:**
   - Фальстарт: **−6**.
   - Овертайм: **−2 балла/сек**.
   - Поворот кисти присоски: **−5**.

## 6. Что сейчас НЕ РАБОТАЕТ, сломано или является техдолгом

### 6.1 🔴 Критично: cake-константы FSM не совпадают с проверенным пайплайном

| Параметр | `runtask.grasp1()` (FSM) | `grasp_generic.py` (проверено 22.11) | Последствие |
|---|---:|---:|---|
| Вынос чашки `cup_offset_x` | **30.0 мм** | **125.0 мм** | FSM целится на ~95 мм ближе к базе; торт не берётся |
| Высота касания `z_touch` | 40.0 мм | 37.0 мм (state 40 − прижим 3) | Небольшое расхождение |
| Высота подъёма `z_lift` | 85.0 мм | 80.0 мм | Небольшое расхождение |
| Подход | 75.0 мм | 75.0 мм | Совпадает |

**Почему это важно:** при типичном пикселе торта $v \approx 213$ формула даёт $x \approx 254$ мм при offset 30 и $x \approx 348$ мм при offset 125. Разница ~94 мм — это промах мимо торта и нарушение правила «торт первым».

**Решение:** привести `grasp1()` к проверенным константам либо заменить его вызовом `grasp_generic.plan_grasp()` / `execute_sequence(return_cube=False)`. После правки — прогнать 141 теста и один полный cake-first прогон.

## 9. Операционный регламент: как запускать робота

### 9.1 Боевой FSM (соревновательный заезд)

1. Включить питание робота, дождаться загрузки NUC (~30 с).
2. На Windows дважды кликнуть **`auto\launchers\START_ROBOT.bat`** (или `connect.ps1`).
3. Подтвердить сохранённый IP (`Enter`) или ввести новый.
4. В дашборде выбрать **`1`** — запуск всех систем (база, камера, лидар, рука, стрим, детектор, `runtask`, bag).
5. Проверить картинку `http://<IP>:8080/`.
6. Поставить робота на стартовую позицию.
7. Старт миссии:
   ```bash
   rostopic pub /task_start_flag std_msgs/String "data: 'start'" --once
   ```
8. Аварийный стоп:
   ```bash
   rostopic pub /task_start_flag std_msgs/String "data: 'stop'" --once
   ```

Меню дашборда:

```text
1) START ALL SYSTEMS          6) STOP ALL SYSTEMS
2) TEST CUBE GRASP            7) DIAGNOSTICS & SYSTEM TEST
3) TEST CUBE RELEASE          8) VIEW DETECTOR LOG
4) SMOOTH KEYBOARD TELEOP     9) MISSION BAGS
5) VIEW LIVE RUNTASK LOG      0) Exit to bash
```

### 9.2 Полевой тест захвата (новый, 22.11)

1. Дважды кликнуть **`run_grasp_test.bat`** в корне `D:\NXROBO`.
2. BAT проверит SSH, зальёт `grasp_generic.py`, `robot_view.py`, `match_logic.py`, `runtask.py`, `detect_ros.py`, `pad_detect.py`, `patch_swiftpro.py`, `snap.py`, `run_grasp_test.sh`, калибровки, перезапустит детектор.
3. Выбрать режим:
   - **`1` — FULL grasp test:** опускание → вакуум → подъём → удержание 5 с → возврат → парковка.
   - **`2` — VIEW ONLY:** аннотированный снимок, без движения; BAT скачает `snapshots/robot_view_latest.jpg`.
   - **`3` — SCAN ONLY:** текстовая оценка цели, без движения.
4. Полезные флаги на роботе:
   ```bash
   python3 -u ~/codes/grasp_generic.py --no-place   # только захват и удержание
   python3 -u ~/codes/grasp_generic.py --scan-only  # без движения
   python3 -u ~/codes/robot_view.py                 # только снимок
   python3 -u ~/codes/grasp_generic.py --hold 3     # изменить удержание
   ```

> ⚠️ **Перед запуском BAT обязательно выполнить §6.2:** BAT заливает локальный `transform_3d.dat` от 21.11 и мог уже затереть фит 22.11 в 19:20. Сначала проверить md5/бэкапы и восстановить матрицу.

### 9.3 Только зрение

- **`run_scan_only.bat`** — заливка кода + `run_grasp_test.sh --scan-only`.
- **`run_grasp_test.bat` → `2`** — view-only.
- На роботе:
  ```bash
  bash -l ~/codes/run_grasp_test.sh --view
  bash -l ~/codes/run_grasp_test.sh --scan-only
  ```

### 9.5 Важно при ручном рестарте детектора

Приватные параметры ROS переживают `pkill`/рестарт. Если детектор когда-либо запускался с `_cake_conf:=...` или `_cake_site_conf:=...`, перед обычным запуском удалить их:

```bash
rosparam delete /detector_node/cake_conf
rosparam delete /detector_node/cake_site_conf
```

`start_system.sh` и `run_grasp_test.sh` делают это автоматически; при ручном `rosrun`/`python3 detect_ros.py` — делать самому.
