# Mission & Navigation Algorithm

Status: design. No code yet. Everything below is intended to be implementation-neutral
pseudocode first, ROS bindings second.

---

## 1. Scope

**In scope (this workstream):**

- Mission execution: task list, ordering, deadlines, stopping conditions.
- Chassis navigation: go-to-pose, arrival checks, recovery, re-localization.
- Belief: what the robot currently believes about cubes, stations and its own pose.
- Supervision: the agreement gate that admits or rejects physical actions.

**Out of scope:**

- Detector model training and fine grasp alignment (arm side).
- Arm IK, vacuum control, precise place trajectories (arm side).
- Mapping/SLAM as a research problem — use `map_server` + a static map for reproducible
  tests; `gmapping` only on the real arena for the Phase 2 map.

**Design constraints:**

- 10-minute match ⇒ internal budget 540 s (`MatchClock`).
- Cake must be delivered to Zone A first; other classes go to the zone given by the
  classification board.
- Arm actions are assumed irreversible enough that a wrong pick costs time; the gate
  must prefer "skip and continue" over "pick blind".
- The same mission code must run in simulation, in unit tests, and on the robot.

## 2. The three sources of truth

| Source | Holds | Updated by | Trust model |
|---|---|---|---|
| **MapKnowledge** | arena geometry, zone poses, station approach poses, board→zone mapping, static obstacles, cube inventory (class, count, home station) | config, board read at match start | Prior. Geometry correct unless measured wrongly. Never expires. |
| **Perception** | detections: `class`, `confidence`, world pose, timestamp | camera + detector (`/objects`), real or simulated | Evidence. Noisy, class ambiguity and false positives possible. Stale after ~0.5 s. |
| **MissionMemory** | task list, per-cube status, attempt counts, station visit history, event log | mission executor (after each action/verdict) | Commitments and history. Can be wrong; perception may contradict it and force revision. |

They "check each other" through the **agreement gate** (§4): before a physical action,
the three must not contradict each other. If they do, the action is refused and the
mission does something safer (re-scan, re-frame, defer, skip).

### 2.1 Cube status model (memory)

```
pending ──confirmed──▶ pending_confirmed ──picked──▶ carried ──placed─▶ delivered
   │                         │                          │
   │                         │                          └─ place failed ─▶ likely_lost
   ├── gate fail ×N ────────▶ skipped
   └── perception sees while memory says delivered ─▶ conflict ─▶ re-check ─▶ revision
```

Statuses are per **class instance slot** (e.g. `bear_1`, `bear_2`, `bear_3`; the sim
scenario spells the class `doll` — see open question 6), but the destination is per
**class** (board mapping). The cake is the only instance-pinned cube (it sits on the
centre brick, tier 2, and must go to A first).

## 3. Mission model

A mission is a YAML list of steps. The executor is generic; the scenario lives in data.

```yaml
name: demo_pick_deliver
clock_budget_s: 540
steps:
  - goto:   {point: Sorting_N, tol: 0.08}
  - pick:   {class: cake, station: N, attempts: 3}
  - goto:   {point: Collection_A_approach, tol: 0.06}
  - place:  {zone: A, level: 1}
  - verify: {class: cake, zone: A, timeout_s: 3}
```

Point names come from `codes/scenario.json` (generated by `make_arena.py`). "Center"
means the 3×3 brick cluster at `(0, 0)`; the robot works it from a `Sorting_*` approach
pose. The discrete mock implements these as `goto_local` / `pick` / `drop`.

Step semantics:

| Step | Meaning | Success condition |
|---|---|---|
| `goto` | navigate to a named pose or `[x,y,yaw]` | pose within `tol` and settled for 0.5 s |
| `read_board` | read classification cards and set class→zone mapping | mapping complete or fallback used (log it) |
| `pick` | confirm target with the gate, then call arm | arm returns `ok` **and** gate passed |
| `place` | place at zone/level via arm | arm returns `ok` |
| `verify` | independent camera check that the cube is at the zone | detection of class at the zone within timeout |
| `wait` | settle time | elapsed |
| `branch` | conditional step (e.g. on map confidence) | condition evaluated once |

### 3.1 Executor states

```
IDLE
  └─ task_start_flag = start ─▶ PRECHECK
PRECHECK   (calibration guard, topic availability, clock)
  └─ ok ─▶ EXECUTE ; fail ─▶ ABORT
EXECUTE    (next step from task list)
  ├─ goto  ──▶ NAVIGATE ──▶ ARRIVED ─▶ EXECUTE
  │                 └─ BLOCKED/ABORTED ─▶ RECOVERY ──▶ EXECUTE
  │                 └─ UNREACHABLE ─▶ mark step failed ─▶ RE-PLAN ─▶ EXECUTE
  ├─ pick  ──▶ GATE ──▶ (pass) ─▶ ARM_PICK ─▶ EXECUTE
  │              └─ (fail) ─▶ RESCAN (×M) ─▶ skip ─▶ EXECUTE
  ├─ place ──▶ ARM_PLACE ─▶ VERIFY_PLACE ─▶ EXECUTE
  └─ verify ─▶ VERIFY_PLACE ─▶ EXECUTE
EXECUTE (list empty) ─▶ DONE
Orthogonal: PAUSED (stop_flag), RELOCALIZE (pose uncertainty), ABORT (clock/stop/fatal)
```

## 4. The agreement gate

The gate is a small function returning `PASS`, `FAIL(reason, action)` or
`CONFLICT(reason)`. It is evaluated **before** `pick` and **after** `place`.

### 4.1 Before pick — `gate_pick`

Thresholds are config values, tuned later; defaults suggested in brackets.

| ID | Check | Inputs | Fail action |
|---|---|---|---|
| **G1** | Requested class is seen with enough evidence | temporal voting over last N=5 frames, ≥K=3 votes for the requested class, confidence ≥ 0.35 (prod value) | `RESCAN` — rotate/step and take a new window |
| **G2** | Observed pose agrees with the map | cluster centre within R_STATION [120 mm] of the nearest pending instance with a known position, else of `map.station_pose(station)` | `RESCAN`; if it persists, **revise belief** — cube moved, or wrong station |
| **G3** | Memory does not forbid the action | status is `pending`; if `delivered` → `CONFLICT`; if `carried` → `FAIL(SKIP)` | `CONFLICT` → second scan window; if still seen, revise memory (perception wins) |
| **G4** | Target is physically approachable | inside station's arm-reachable zone, not inside an obstacle / inflated costmap | `REFRAME` — move to an alternate approach pose and re-scan |
| **G5** | Enough match time remains | `clock.remaining > step_cost_estimate + reserve` | `RE-PLAN` without this pick |

Rules that keep the gate honest:

- **Perception must not be a single frame.** G1 uses the same temporal voting as the
  production detector, so a one-frame false positive cannot authorize a pick.
- **Map is a prior, not an oracle.** If perception consistently disagrees with G2, the
  gate updates the belief instead of repeating the same failed action (this is exactly
  the production bug SI-30: re-scanning the same empty point forever).
- **Memory never overrides direct evidence silently.** A `CONFLICT` is logged as an
  event; the revised status is used for the rest of the mission.

### 4.2 After place — `gate_place`

| ID | Check | Inputs | Fail action |
|---|---|---|---|
| **V1** | Arm reports placement success | `arm.place()` result | if false → retry once → mark `likely_lost`, continue |
| **V2** | Independent visual confirmation | after the arm retracts, detect the class within R_ZONE [150 mm] of the zone centre, ≥3 of 5 frames, conf ≥ 0.35 | if timeout → `UNVERIFIED` (do not lie), continue |
| **V3** | Location sanity | detected pose inside the zone square, not on a tower edge | if false → mark `misplaced`, log event |

`delivered` is recorded only when V1 **and** V2 pass. V1-only is recorded as
`delivered_unverified` — the mission does not claim a score it cannot observe.
(The real robot currently has no vacuum feedback at all — SI-28 — so V2 is the only
independent evidence available.)

### 4.3 Pose and navigation sanity (orthogonal)

- AMCL covariance above threshold, or scan-to-map mismatch → `RELOCALIZE`:
  stop, rotate in place in 45° steps, take a scan at each, resume when confident.
- `move_base` goal `ABORTED` → recovery ladder (§6.2).
- If the robot's pose estimate disagrees with the arrival check by more than
  `tol + margin`, treat as arrival failure even if `move_base` says SUCCEEDED.

## 5. Pseudocode

### 5.1 Mission executor

```
run_mission(world, mission, services):
    clock   = MatchClock(mission.clock_budget_s)
    memory  = MissionMemory(mission.steps, world.cubes)
    belief  = Belief(map=world)
    wait_for_start_flag()

    for step in mission.steps:
        if stop_flag:            return ABORT("operator stop")
        if clock.expired():      return ABORT("match clock")
        if not precheck(step):   continue          # skip impossible step, log

        outcome = execute(step, world, belief, memory, services)
        memory.record(step, outcome)

        if outcome == FATAL:     return ABORT(outcome.reason)

    return DONE(memory.report())
```

```
execute(step, ...):
    match step:
      GOTO:
        return navigate(step.point, step.tol)

      PICK:
        for attempt in 1..step.attempts:
            verdict = gate_pick(belief.scan_window(), step.class, step.station, memory)
            if verdict.pass:
                result = services.arm.pick(step.class, step.station)
                memory.mark(step.class, picked=result.ok, confirmed_class=result.confirmed_class)
                if result.ok:  return OK
                else:          return RETRYABLE(result.reason)   # arm failed, cube may remain
            if verdict.action == RESCAN:
                reframe_and_rescan(verdict)                      # rotate/step, new window
            elif verdict.action == REFRAME:
                move_to_alt_approach(step.station); reframe_and_rescan(verdict)
            elif verdict.action == SKIP:
                return SKIPPED(verdict.reason)                   # never pick blind
            elif verdict.action == REPLAN:
                return REPLAN_REQUESTED(verdict.reason)
        memory.mark(step.class, skipped=True)
        return SKIPPED("gate attempts exhausted")

      PLACE:
        nav = navigate(step.zone, step.tol)
        if nav != ARRIVED: return FAILED("cannot reach zone")
        r = services.arm.place(step.zone, step.level)
        v = verify_place(step.class, step.zone, timeout=3.0)
        memory.mark(step.class, placed=r.ok, verified=v)
        return OK if (r.ok) else RETRYABLE

      VERIFY:
        v = verify_place(step.class, step.zone, step.timeout_s)
        memory.mark(step.class, verified=v)
        return OK if v else UNVERIFIED

      READ_BOARD:
        m = read_board_with_voting(attempts=3)
        belief.set_mapping(m or world.default_mapping)
        return OK
```

### 5.2 `gate_pick`

```
gate_pick(window, requested_class, station, memory):
    dets = cluster(window, radius=R_CLUSTER)            # same idea as prod cluster_detections
    best = argmax votes(d) for d in dets
           where d.class == requested_class and d.conf >= CONF_MIN

    if votes(best) < K_VOTES:                 return FAIL(RESCAN,  "G1 class unconfirmed")
    if dist(best.pose, map.station_pose(station)) > R_STATION:
                                              return FAIL(RESCAN,  "G2 pose mismatch",
                                                          revise=best.pose)
    if memory.status(requested_class) == CARRIED:
                                              return FAIL(SKIP,    "G3 already carrying")
    if memory.status(requested_class) == DELIVERED:
                                              return CONFLICT("G3 memory says delivered",
                                                              evidence=best.pose)
    if not reachable(best.pose) or in_costmap(best.pose, inflation):
                                              return FAIL(REFRAME, "G4 not approachable")
    if clock.remaining < cost_estimate(step):
                                              return FAIL(REPLAN,  "G5 time")
    return PASS(best.pose)
```

Conflict resolution (G3):

```
on CONFLICT:
    second = gate_pick(take_new_window(), ...)
    if second.pass:  memory.revise(class, status=PENDING, note="perception override")
                     log_event("memory_conflict_revised", ...)
    else:            return SKIP("conflict unresolved")
```

### 5.3 `verify_place`

```
verify_place(class, zone, timeout):
    wait(arm.retract + settle)                 # camera must not be blocked by the arm
    deadline = now + timeout
    window = []
    while now < deadline:
        window += belief.scan_window()
        if votes_for_class_at(window, class, zone.centre, R_ZONE) >= K_VOTES
           and pose_inside(zone, best.pose):
            return VERIFIED
        if count_detections(window) >= N:      # enough evidence, wrong place
            return MISPLACED(best.pose)
        wait(frame_period)
    return UNVERIFIED
```

### 5.4 Navigation

```
navigate(point, tol):
    pose = map.resolve(point)
    for attempt in 1..2:
        r = nav.go(pose)                        # move_base action, real or simulated
        if r == SUCCEEDED and within(pose, tol) and settled():
            return ARRIVED
        if r == ABORTED or NOT_REACHED:
            recovery_ladder()
            continue
        if pose_uncertain():
            relocalize()
    return BLOCKED
```

### 5.5 Recovery ladder (per goal, max 2 cycles)

```
recovery_ladder():
    1. clear costmaps (global + local)
    2. rotate in place slowly, take a fresh scan
    3. back up 0.20 m if rear is clear
    4. recompute path; if still blocked -> mark goal unreachable
```

### 5.6 Implementation notes (`codes/mission_logic.py`)

- **Conflict re-check bypasses G3.** When perception contradicts memory, the second
  window is evaluated with the memory veto disabled; memory is revised only if G1/G2/G4/G5
  pass. Without this, the re-check could never pass (G3 would still say "none pending").
- **A failed pick leaves the cube pending.** Only `PickResult.ok` calls `mark_picked`.
  Marking on failure would make the retry hit "G3 already carrying" — this was a real
  bug found by running the demo against seed 7, now covered by a regression test.
- **No pose means no spatial claim.** `verify` returns `unverified` when detections have
  no world pose (the discrete model), rather than falsely reporting `misplaced`.
- **The platform protocol is duck-typed** (module docstring). `mock_adapter.py` implements
  it on the discrete model; `fake_world.SpatialPlatform` implements it on the continuous
  world (drive, lidar, detections with poses, mocked arm). The ROS node will implement
  the same methods.
- **G2 matches the nearest pending instance with a known position.** In the spatial world
  each brick carries its mapped position, so a detection is compared with the cube it
  most likely is — not with the chassis approach point. If no positions are known, G2
  falls back to the station pose.

### 5.7 Re-plan

The demo mission is a fixed list; re-planning only removes/completes steps:

```
replan(memory):
    drop steps whose target is marked skipped or unreachable
    move `verify` before any dependent `place` if the cube is carried
    if cake not delivered and another cube is carried -> deliver that cube to its zone,
      then attempt cake (cake rule gives points only if it is first to A, so once another
      cube is delivered, cake score is already lost; still deliver it for partial credit)
    stop when task list is empty or clock expires
```

## 6. Demo scenario walkthrough (A → center → pick → A)

| # | Step | Robot does | Gate / evidence | Metric recorded |
|---|---|---|---|---|
| 1 | `goto Sorting_N` | leave A, approach the brick cluster | none (nav only) | arrival error, time, "left A" point |
| 2 | `pick cake` | gate → arm mock | G1 class, G2 pose, G3 memory, G4 reach, G5 time | gate verdict, attempts |
| 3 | `goto Collection_A_approach` | carry to A | none | path length, time |
| 4 | `place A level 1` | arm mock (`drop()`) | V1 | - |
| 5 | `verify cake at A` | camera check | V2, V3 | verified / unverified / misplaced |

The earlier version also drove A → center → A before picking. That round trip is a useful
navigation-accuracy test, but it doubles the mission time for no task benefit; keep it as
a separate mission file if it is ever needed.

Optional preamble: `goto Classification_area` + `read_board` before step 1 (the discrete
mock's baseline strategy does this). `verify` is not implemented in the discrete mock —
it needs a perception source. In Level 0B (`fake_world.py` + `run_live.py`) it runs and
passes: the cake is detected inside zone A after placement.

**Injected fault cases for Level 0 tests** (deterministic seeds):

1. Class mismatch: detector reports another class where the cake should be → gate must
   skip, no arm call.
2. Ghost cube: detector reports a cube at a station where memory says already delivered
   → conflict → second scan → revision logged.
3. Single-frame false positive: one frame sees the target, four do not → gate must fail
   G1 (voting).
4. Nav abort: `move_base` returns ABORTED once → recovery ladder → succeeds on retry.
5. Pose drift: fake world shifts ground-truth pose mid-run → arrival check must fail and
   trigger relocalization.
6. Arm failure: mock returns FAIL on first call, OK on second → mission retries once.
7. Slow clock: budget shortened so G5 denies the last pick → mission finishes cleanly.

## 7. Failure policy summary

| Event | First response | Second | Final |
|---|---|---|---|
| No cube seen at station | new window after re-frame | alternate approach pose | skip station, continue |
| Class mismatch | new window | skip | log loss |
| Pose mismatch vs map | new window | revise belief + re-plan | skip |
| Memory says delivered, camera sees it | second window | revise memory | log conflict |
| `move_base` ABORTED | recovery ladder | second ladder | unreachable, re-plan |
| Localization drift | relocalize | relocalize from known point | abort mission |
| Arm pick fail | retry once (cube may remain) | mark skipped | continue |
| Place verify timeout | look around zone once | mark unverified | continue |
| Stop flag | finish current atomic action | stop all motion | ABORT |

## 8. Metrics and acceptance (Level 0)

Metrics logged per run (JSONL, one record per step + summary):

- arrival error per waypoint (m) and settling time (s);
- leg duration and total mission duration vs 540 s;
- gate verdicts by reason, picks attempted / succeeded;
- verification outcomes (verified / unverified / misplaced);
- false delivery rate = memory `delivered` ∧ ¬V2;
- recovery events, relocalizations;
- collisions/contacts (sim bumper events).

Level 0 acceptance:

- The demo mission completes end-to-end in ≥ 5/5 deterministic seeds.
- All 7 injected faults are caught with the specified action (no arm call on a failed gate).
- No waypoint overshoot above tolerance persists across seeds.
- A run produces a machine-readable trace that reconstructs, for every action, what each
  of the three sources believed at that moment.

## 9. Open questions (to settle before coding Level 0)

1. **Arena coordinates** — fixed by `make_arena.py`: A top-left, B top-right, C
   bottom-right, D bottom-left; collection centres at ±1.275 m; start in A. Confirm
   against the real field when the arena is built.
2. **Station poses** — `Sorting_N/S/E/W` in `scenario.json` are approximate stand-ins
   ((0, ±0.38), (±0.38, 0)). Production also has `Sorting_M` for the cake, but the sim
   has no `M`: the cake sits on the centre brick and is picked from any `Sorting_*`
   approach. Decide whether to add `M` to the map or change `CAKE_SORTING_STATION`.
3. **Board read position** — `make_arena.py` puts the board on the sorting table on the
   west wall (`Classification_area` at (-0.90, 0)), read by a robot facing west, left →
   right = south → north = zones B, C, D. Confirm this against the real board.
4. **Tower stacking** — the demo places on level 1 only. Levels 2/3 change the arm
   contract (`place(zone, level)`) but not the mission logic; confirm the arm side
   will own tower alignment.
5. **Gate thresholds** — `K/N=3/5`, `CONF_MIN=0.35`, `R_STATION=120 mm`, `R_ZONE=150 mm`
   are starting values (config/gate.yaml) to tune in sim.
6. **Class naming** — the sim scenario uses `doll`; production canonicalises the same
   cube as `bear` (id 1). Pick one spelling before `mission_logic.py` is written.
